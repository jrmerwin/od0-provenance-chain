# DEU Model Genealogy and Claim-to-Source Reconciliation

## Scope and method

This is a read-only provenance audit of the four supplied PDFs, the complete `RMR_logical_Seed` and `RMR_DEU` trees, eight discovered Git repositories and all discovered ZIP archives. Source copies are identified by SHA-256, not filename. `source_inventory.csv` records 72 relevant copies representing 42 distinct hashes; `claim_occurrences.csv` records 2,119 scoped exact-term occurrences. `archive_inventory.json`, `git_repositories.json`, and `paper_pdf_matches.json` preserve the archive/history evidence.

The linked repositories were checked at their available heads: `generative-ledger` commit `30c122d9cd646eaecc70c0cdd06f7ed4be2e4176` (2026-07-06) and `forces_unification` commit `8f6c942e317ee66c5fec2041c6b48d9cc9f60f7a` (2026-07-10). Neither has tags; the latter has only the main branch and stops at v30.

## Principal result

The papers combine several non-isomorphic model families:

1. a 137-object recursive unordered DAG-7 registry;
2. a causal event-DAG foam in `deu_exp456_minimal.py`;
3. 01N/01Q fixed-epoch coherent-stitch surrogates;
4. the v7-v30 live triangulated scheduler line;
5. standalone scalar/complete-bipartite psi0 and closure-amplitude harnesses;
6. analytic one/two-queue reductions; and
7. manuscript-only cross-model dictionaries and the unavailable v31/G2c line.

No source implements a single shared state space spanning these families. In particular, the linked `forces_unification/CONTINUITY_LEDGER.md` explicitly records “432 / registry-foam identifications” as blocked, while Paper 1 treats that identification as native.
